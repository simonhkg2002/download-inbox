# 產品定義（Product Brief）

建立日期：2026-10-28
狀態：方向已選定；互動及技術選擇待原型驗證。

## 問題

下載當下最清楚檔案的用途，但打開 Finder、重新命名和移動需要多次操作。延後整理容易留下難以辨識的檔案名稱。

## 核心假設

以低打擾的卡片把命名和歸檔集中在一起，能降低使用者延後整理的比例。此假設尚未經使用者測試驗證。

## 第一版互動

1. 透過系統選擇器取得資料夾存取權限。
2. 等待新檔案下載完成，避免把暫存下載當作完成檔案；具體判定方式需技術驗證。
3. 顯示卡片，保留原副檔名，提供名稱及目的地選擇。
4. 儲存成功後顯示結果和撤銷入口。
5. 稍後處理或逾時收起卡片，檔案留在原處並出現在待整理清單。

## 互動原則

- 使用者確認後才重新命名或移動。
- 同名檔案不自動覆寫；提供清楚的重新命名選項。
- 最近目的地只作建議，不代表允許自動移動。
- 多個下載應排隊或合併，避免大量彈出卡片。
- 提供暫停提示，讓使用者能在方便時批次處理。
- 撤銷前驗證檔案狀態；遇到外部變更或原路徑被占用，清楚說明無法還原的原因。

## 暫不納入第一版

- AI 自動命名、內容分析、自動分類。
- 雲端同步及帳戶系統。
- Windows 或 Linux 支援。

## 驗證方式

- 先以測試檔案走完下載、命名、移動、稍後處理及撤銷流程。
- 記錄是否減少操作步驟，以及提示是否造成打擾。
- 邀請少量使用者以自己的情境測試，依回饋決定是否擴充。
- 專案初期推廣目標為取得首 20 顆 GitHub 星星（Stars），並以實際使用回饋判斷產品價值。
